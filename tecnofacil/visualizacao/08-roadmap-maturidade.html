3. Definition of Operation v1.0 — Critérios para sair do Draft

Todos os critérios abaixo precisam ser verdadeiros para promover a aplicação de draft para v1.0 operacional:

  • Os 3 Modelos de Referência estão escritos com todas as Etapas tendo critério de conclusão e output declarados (Leva 1 — concluída)
  • Pelo menos uma Instância de cada Processo Comercial (Presencial e Digital) completou Fase 1 → Fase 4 com lead real, terminando em contrato ou desqualificação explícita
  • Pelo menos uma Instância do Processo Operacional completou Fase 1 → Fase 4 com cliente real recebendo todos os entregáveis do pacote contratado
  • O handoff Comercial → Operacional foi exercitado pelo menos uma vez, sem perda de contexto entre Setores
  • Padrões de loop e cascata de insucesso foram exercitados em pelo menos uma Instância

5. Riscos Conhecidos e Mitigacoes

Risco
Cliente some no meio da Fase 3 (pago, para de responder briefing/validações)
Mitigacao
Quick Win cedo cria engajamento; SLA pausa quando bloqueado por externo; cláusula contratual prevê cobrança proporcional
Risco
Quick Win não é percebido como valor pelo cliente — fica frio esperando o resto
Mitigacao
Só fechar a Etapa 2.3 quando o cliente verbaliza valor percebido (não apenas "recebido")
Risco
Identidade visual indefinida atrasa toda a Fase 3 (Site, Landing e Instagram travam)
Mitigacao
Etapa 1.2 (Briefing) tem item obrigatório de identidade visual; se cliente não tem, oferece sub-entregável de criação mínima como add-on
Risco
Volume de Manutenção (Fase 5) cresce e gargala o Rodrigo
Mitigacao
Modelar limite por pacote; iniciar Leva 2 com agents (Eva para recorrências) cedo
Risco
Modelos de Referência envelhecem sem revisão
Mitigacao
Cadência semestral de revisão; gatilho quando Instância gera learning significativo
